# 笔记计划与选图

完整阅读转录和拼图后，分别写提炼版与详细材料。`reader` 输出给人看的 `笔记.md`；顶层的 `title`、`summary`、`sections`、`uncertainties` 输出 `详细资料.md`。两份文档不能只在有无时间戳上不同，主笔记需要重新提炼和组织。

```json
{
  "reader": {
    "title": "先定内容，再提高画质",
    "summary": "先用小尺寸确认内容，再复用结果做高画质输出，可以减少重复生成。",
    "sections": [
      {
        "heading": "怎么用",
        "body": "1. 先完成小尺寸生成，确认内容。\n2. 保存结果，再调整画质并细化。",
        "images": []
      },
      {
        "heading": "关键设置",
        "body": "只保留影响理解或使用的核心参数，必要时用小表格。",
        "images": []
      }
    ]
  },
  "title": "工作流详细资料",
  "summary": "详细操作、画面证据与回看索引。",
  "review": {
    "full_transcript_read": true,
    "all_contact_sheets_viewed": true
  },
  "sections": [
    {
      "heading": "输出尺寸设置",
      "start": 0.0,
      "end": 18.0,
      "body": "记录完整设置、适用条件和证据，重要参数须能在转录或画面中找到。",
      "images": [
        {
          "file": "frames/frame-00001.png",
          "caption": "输出尺寸设置",
          "reason": "参数仅在画面出现，保留原图便于核对。"
        }
      ]
    }
  ],
  "uncertainties": []
}
```

示例只说明结构，不是每条视频必须照套的文案。顶层详细章节的 `start` / `end` 是源视频秒数，截图时间须在章节内（允许 1 秒误差）。`reader.sections` 按信息主题组织，无需时间字段，可以合并多个详细章节。

图片 `file` 使用 `analysis/frames.json` 的实际 image 值，或 `capture` 登记在 `analysis/details.json` 中的文件；不能照抄示例名。两层文档的图片均需 `caption` 和 `reason`，没有必要配图时用 `images: []`。主笔记的图要帮助理解，证据性截图放详细资料；同一原图可共用，脚本不重复复制。

## 提炼原则

- 用一句核心结论开头，再给少量关键方法、参数、条件或比较。按信息重要性组织，不按“视频先讲什么、接着讲什么”复述。
- 对短视频，主笔记通常应能很快读完。长短随信息量，不凑字数、不把全部信息挤进主笔记。
- 不在主笔记插入时间戳、来源核验过程、转录纠错记录、反复的“作者说／画面显示”或逐张截图解说。使用“演示参数”等简短限定即可保持依据边界。
- 涉及操作选择的关键约束必须保留，例如硬件条件；完整安装细节、模型文件名、证据冲突分析放详细资料。不能因压缩而隐藏会改变结论的不确定性。
- 原图比文字更直观时再配图。一个小表格能说明的参数不必再配相同内容的截图。
- 纯观赏视频提炼展示内容和已给出的制作信息；没有讲到的方法、模型和参数不能补造。

## 证据与验收

`review` 是实际审阅记录，没看过不能填写 true。术语修正另外保存到工作目录 `analysis/corrections.json`，如 `[{"start":12,"raw":"识别原文","corrected":"核实后的名称","basis":"画面 00:12.4 可见名称"}]`；不改原始转录。

主笔记独立读懂、信息清晰、没有逐段复述；详细资料能支持主笔记中的结论，并保留必要时间与证据。核对图片存在且可读、相对链接可用、时间不越界、局部裁剪有标注。细字看不清不猜，代码无法辨认不生成看似可运行的补全。
